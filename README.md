# sg0hann SoundSwap

A Windows desktop app with a single-file installer for selecting BuildTopia sounds for the supported Creative Destruction sound archive. It follows the selected dark amber design, with compact weapon cards, a folder picker, sound previews, original-file restore and automatic backups.

## Install and run

1. Download **sg0hann-SoundSwap-1.2.0-Setup.exe** from Releases.
2. Close any running SoundSwap window and run Setup.exe. It installs for your Windows account and creates a desktop and Start menu shortcut.
3. Open SoundSwap, close Creative Destruction, browse to the game folder, select sounds and Apply.
4. **Fully close SoundSwap after applying. The sounds stay installed and work without it running.**

Runtime files stay in the app’s installation directory. You do not need to extract or manage a portable folder. Later installers update the same installation and preserve settings, custom images and backups. Uninstall through Windows Settings → Apps. Removing SoundSwap does not restore game sounds; use Restore original first if desired.

## Updates

The app checks stable GitHub releases at startup and every four hours while running. Settings also has a manual check. The popup downloads Setup.exe; close SoundSwap and run it to update. Installation is manual. Version 1.1.0 users receive a compatibility ZIP containing just the installer and instructions. Sound selection works offline; a fully closed app cannot show popups.

## What is included

- Dark amber desktop interface with smaller weapon illustrations, tabs, category filters, search and live selection count.
- 65 catalog entries across weapons, vehicles, traps and related effects. One unavailable source entry (M82A3) stays disabled.
- Actual decoded BuildTopia preview clips for 63 entries. Effects without source audio do not have a play button.
- Individual choices for banks that have different source audio. Items whose audio is already identical are labelled and disabled, because switching them would make no audible change.
- Checks before writing and immediately before committing the new archive. If the game is running or process status cannot be checked, Apply and Restore are blocked.
- A first-install backup under the app's user-data folder, available from **Settings → Open backup folder**.
- Validation of the original archive, donor resource hashes, rebuilt resource bounds and generated bytes.
- Atomic replacement of `res\wwise.npk`; temporary files are verified and removed if an operation fails before commit.
- Existing supported v1–v4 packs and compatible app-generated selections can be detected.
- Right-click any card to import a PNG, JPG or WebP item image. Images remain local to that PC.

Matching cards use the **24 supplied game images**, including both pistol images on the shared 92F/P229 card. All images can be viewed in Settings. C111 remains unassigned until its sound bank is confirmed. Cards without supplied matching artwork keep their previous placeholders. Some special items retain source-bank labels until an exact in-game name is confirmed. The preview screenshot and generic illustrations do not determine sound routing: the supplied archive's bank IDs and metadata do.

## Known naming and source limits

- DTR is routed to `weapon_tsg`, UMP9 to `weapon_tsmg`, and Uzi to `weapon_smg`, based on the source clip names.
- **92F / P229** is a single pistol-bank selection. Their exact independent in-game routing has not been verified, so the app does not pretend they can be changed separately.
- **S1897 / Pump** follows the supplied game image and source filenames. Earlier testing called it M1915; sound routing is unchanged.
- M82A3 has no matching donor bank. It is unavailable.
- “Coke propeller” has not been identified and is not claimed as an available option.
- The supported pristine original archive is 127,929,852 bytes, SHA-256 `32807ac089ead7068ddc2820759198964434069661ffbe2cd22c1149956df71b`. Other game builds are refused rather than overwritten.

## Test status

The earlier merged weapon packs were tested in-game by the user. Badges preserve those reports, including working AK-47, SCAR, XM8, DTR, pump shotgun, Uzi, UMP9, AWP, VSS, VHS, pistol/revolver and M134 sounds. New vehicle and trap choices still need in-game testing.

For this app build, automated engine tests cover selective resource changes, preserving unselected resources, AK-to-SCAR switching, exact original restore, first-backup preservation, corrupted/unknown archive rejection, running-game blocking and a game starting during a build. UI tests cover selection, search, filters, tabs, previews, apply/restore states and compact-window layout. Native Electron startup and the isolated preload/IPC bridge were checked on Linux. The **Windows executable, real Windows process enumeration and gameplay with selections still require a Windows test**.

This app does not edit the launcher, anti-cheat or game executable. It only changes the selected supported sound archive while the game is closed.

## Source build

The repository includes prepared data and preview assets. Original archive parts are automatically reconstructed and SHA-256-verified by npm commands. You do not need to regenerate the catalog to build the app.

```powershell
npm install
npm test
npm start
npm run package:win
npm run installer:win
```

Use Node.js 22.12+ or 24+. The package versions are pinned in `package-lock.json`. `npm run package:win` writes the portable app directory under `dist`.

`tools/prepare_catalog.py` documents the source-archive preparation used for this build; it expects the original supplied archives, the analysis helpers and vgmstream/ffmpeg in the workspace layout used during development. It is not needed for normal app development or rebuilding this prepared source package.

Sound archives and clips came from the files supplied in this project. Placeholder artwork was generated for the design preview. Electron's bundled licenses are included in the Windows distribution.

## Publishing releases

Bump package.json and package-lock.json versions, update RELEASE-NOTES.md and push to main. GitHub Actions tests and builds the Windows app, then publishes v<version> with a Windows ZIP and checksum. Existing releases are not overwritten.
